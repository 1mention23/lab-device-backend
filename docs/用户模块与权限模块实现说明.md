# 用户模块、权限模块实现说明（A 负责部分）

## 1. 模块组成

| 子模块 | 核心类 | 功能 |
|---|---|---|
| 登录模块 | `AuthController`、`TokenService` | 账号密码校验、签发 token、退出登录、查询当前用户 |
| 用户模块 | `UserController`、`User`、`UserRepository` | 用户新增、查询（按角色/关键字）、修改、启用/禁用、删除 |
| 权限模块 | `RequireRole`、`AuthInterceptor`、`WebConfig` | token 登录校验、四种角色接口级权限拦截 |
| 基础数据模块 | `LabController`、`DeviceTypeController` | 实验室、设备类别增删改查 |

## 2. 登录流程

1. 前端 POST `/api/login`，传 `{username, password}`
2. 后端按用户名查 `user` 表，将密码做 SHA-256 十六进制摘要后与库中密文比对（与建库脚本 `SHA2('123456',256)` 一致）
3. 校验账号 `status`（0正常，1禁用），禁用账号拒绝登录
4. 校验通过生成随机 token 存入内存会话表，返回 `{token, user}`
5. 前端之后每个请求携带 `Authorization: Bearer <token>`

## 3. 权限控制流程

1. `AuthInterceptor` 拦截 `/api/**`（`/api/login` 放行）
2. 解析 Bearer token，查内存会话；无效返回 `code=401 未登录或登录已过期`
3. 读取 Controller 上的 `@RequireRole` 注解（方法级优先于类级）：角色不在允许列表返回 `code=403`
4. 未加注解的接口：登录即可访问（如实验室/类别查询，供前端下拉框使用）
5. 拦截通过后把会话（userId、username、role）放入 request 属性，Controller 可直接取当前登录人

## 4. 关键设计

- **统一返回**：`ApiResponse{code,msg,data}` + `GlobalExceptionHandler` 全局异常兜底，业务错误抛 `BizException` 即可
- **字段命名**：Jackson 全局 snake_case，与数据字典一字不差（`user_id`、`create_time`……）
- **密码**：只存 SHA-256 摘要；新增用户默认密码 123456；管理员重置密码即重新摘要入库
- **自我保护**：管理员不能禁用/删除当前登录的自己的账号
- **删除保护**：删除被设备引用的实验室/类别时捕获外键异常，返回友好提示
- **返回数据脱敏**：用户列表通过 `UserVo` 返回，不含密码字段

## 5. 数据库说明

- `user` 表原设计无启用/禁用字段，本模块补充 `status TINYINT NOT NULL DEFAULT 0`（0正常，1禁用），
  补丁脚本：`src/main/resources/sql/user_add_status.sql`
- 其余表结构完全按 D 同学数据字典与 B 同学建库脚本，未做改动
